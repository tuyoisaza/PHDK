# Templates, imports and exports for tabular resources

**Workspace contract (v3.1.0):** `PHDK_FLEXIBLE_DATA_WORKSPACE_STANDARD.md` may implement an optional advanced table interface for applicable imports/templates/exports, but selecting or declining this UI profile never weakens this standard's independent business data-exchange requirements. Saved views and hidden grid columns never expand export permissions; document whether authorized export scope follows filters or selection.


For each first-party managed collection of business records, evaluate **Download template**, **Import** and **Export data** alongside CRUD for every applicable role and surface in `CRUD_MATRIX.md`. Examples include inventory, contacts, orders and service requests. Record the approved formats, permissions, fields, business key, limits, duplicate policy, batch behavior and evidence for each operation. Separate exceptions apply to read-only reports, derived dashboards, singleton settings, security credentials, immutable ledgers and API-only surfaces. Record the reason for each unavailable operation. A user's ability to read a row never implicitly grants bulk export or import.

## Product behavior

| State or action | Acceptance contract |
|---|---|
| Empty authorized collection | Offer a discoverable **Download template (.xlsx)** and **Import**. The template works with zero records and remains available after data exists. It contains the input schema and usable instructions, with zero business rows. Put optional examples or lookups on a separate documented sheet. |
| Template contents | Use the same versioned import schema for headers, stable field identifiers or supported localized labels, column order rules, data types, required fields, length/range limits, date/time and decimal conventions, permitted values, keys and relationships. Identify editable versus system-managed columns. Use synthetic examples. Exclude secrets, personal data, other tenants' lookups and privileged fields. State the expected sheet and first input row. |
| Import | Default to genuine XLSX and CSV for eligible user-managed tables. Track a missing required format as a gap. An established, approved product constraint can justify a format exception. Offer TXT only with an explicit delimiter, field layout or fixed-width specification and encoding. Validate format/content, schema version, headers, types, limits, duplicates and row-level permissions on the server. Show preview or validation feedback, actionable row/column errors, accepted/rejected counts, batch ID and final outcome. Define whether validation is atomic or partial and whether replay skips, rejects or updates matching keys. |
| Populated authorized collection | Offer **Export data (.xlsx)**, with real workbook structure and declared scope: filters, selected records, all matching pages, order and role-visible fields. Export persisted, authorized values. Provide a stable key for reconciliation. If the export has extra display, calculated or read-only columns, document how to map it back to the input schema. |
| Unauthorized role, field or tenant | Enforce permissions and tenant ownership on upload, preview, approval, template lookups and download endpoints. Derive ownership and privileges from the session and server policy. Reject foreign references. Sanitize spreadsheet-bound untrusted cells as literal data according to type and format, including formula-like CSV text. Treat uploaded business inputs as values. Reject formulas in writable input cells or handle them as inert text per the schema. Never evaluate uploaded formulas server-side. Any display formulas or validations in the trusted blank workbook stay outside the imported business values. Enforce upload/expanded-size and row limits and reject unexpected macros, external links or malformed workbooks. |

Use a single resource schema for template generation, import validation and export mapping where possible. Do not export HTML or delimited text under an XLSX extension. For repeatable or multi-format intake apply the project's [Data Import / Intake Pipeline](https://github.com/tuyoisaza/PHDK/blob/main/technical_stack.md#data-import--intake-pipeline) (installed copy: `TECHNICAL_STACK.md`): stage and identify the batch, enforce approval and support audited deactivation. Preview/staging and final persisted business visibility are separate outcomes.

## What the UAT agent does when it needs a file

1. Start at the actual screen as the authorized synthetic persona on the pinned build. Inspect the UI, schema and examples for the resource. Use an empty **run-owned** collection, tenant or filter if the app supports it. Never empty or export real business records just to set up a case. An inability to establish a safe empty state blocks only its dependent cases.
2. Download the product's actual blank template where the role permits it. Verify format and openability, sheet/header names, version and instructions, accepted field types and zero business rows. Record filename, hash, build, role, tenant and case ID. Keep the original intact. If the template is required and is absent, broken or incompatible, record that defect immediately in the [UAT register](UAT_DEFECT_WORKFLOW.md). Use a schema-derived file for independent importer coverage and label its source `GENERATED_FROM_SCHEMA`. It cannot prove the download case.
3. **Create the inputs yourself.** Fill a copy of the downloaded template with fictional Company Co or product-native run-owned records. Derive headers, allowed values and safe relationship IDs from the actual contract and verified synthetic fixtures. Keep IDs unique to the run. Cover matrix-required formats and any additional formats the product advertises. Create an actual file for each applicable format. Include a valid batch and independent invalid variants such as a missing required field, invalid value, duplicate key or cross-tenant reference. Add leading-zero IDs, accented text, quoted delimiters, native dates/decimals or line breaks where relevant. Keep expected values and rejection reasons before uploading. For a file column containing untrusted text, include a harmless formula-like literal where applicable and inspect how the downloaded export represents it. Never enable macros or external links to verify an export.
4. Reopen each file and verify what the parser should see. Keep recipe, source type (`DOWNLOADED_TEMPLATE` or `GENERATED_FROM_SCHEMA`), checksums and expected outcomes in or linked from `UAT_FIXTURE_MANIFEST.md`. The [offline fixture helper](scripts/phdk_uat_import_fixture.py) and [worked recipe](examples/uat-data-exchange/README.md) support ordinary templates. For rich or unsupported layouts use the project's existing workbook library or writer and verify fidelity. An unavailable convenience library does not exhaust those options.
   For example, the agent can render the included CSV recipe in the installed layout:

   ```sh
   python phdk-standards/scripts/phdk_uat_import_fixture.py --template phdk-standards/examples/uat-data-exchange/template.csv --recipe phdk-standards/examples/uat-data-exchange/recipe.json --out uat-inputs-r7k2
   ```

   In a real case, replace both inputs with the downloaded template and the run-specific recipe. The recipe supplies the run key, header and first data row, and records keyed by exact writable column names. For text, declare the encoding and delimiter. For XLSX, name the sheet. Each negative variant names one row, column, replacement and expected result. A fresh output directory keeps the original and prior evidence intact. Delimited text uses the Python standard library. Ordinary unsigned XLSX templates use the already installed openpyxl reader. Templates with structured Excel tables, protected/merged input sheets, external links, signatures or macros require a compatible project adapter or an explicitly documented unsupported-format result. Do not remove template features to manufacture a passing case.

5. Import via the interface during explicit UAT. Verify preview mapping and row-level feedback. On staged intake, first check that pending rows are absent from ordinary business queries. Exercise the authorized approval path, then verify batch counts and list/detail readback after refresh. If policy requires an actual human decision, mark that step MANUAL and continue the permitted cases. Verify failed rows and forbidden fields have no unintended effects, atomic or partial behavior matches the contract, replay follows the duplicate policy and a foreign tenant cannot read or modify the run's records. Keep negative batches separate so an earlier write cannot falsify the next case. Use safe isolated side effects and normal cleanup.
6. Download the populated Excel export from the same scoped view. Reopen the actual XLSX. Match business keys and expected typed values, record count, field visibility and tenant boundary against the persisted data. A successful HTTP response, toast or filename is insufficient. Where export-to-import round-trip is supported, test replay in a clean run-owned scope or use the declared duplicate behavior. Deactivate/remove only the run's batches and verify the expected post-cleanup state.
7. Report **template download**, **import per required or advertised format**, **persistence/validation** and **scoped export** as separate case results, with redacted evidence and actual revision. Continue independent cases when one fails. The default precondition is that the agent supplies its own synthetic file. Ask for a specific external artifact only when the acceptance criterion expressly requires a non-reproducible signed original or proprietary sample unavailable through an authorized fixture source. Request the approved sample or existing signing service without requesting private keys. Finish all reproducible cases first.

The fixture helper builds files offline. Its output is not evidence that a product accepts an upload or exports correct data. Browser and provider activity stay within explicit [UAT](UAT_STANDARD.md). Common CSV quoting rules, the OOXML package format and spreadsheet formula interpretation are documented in [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180.html), [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) and [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection).
