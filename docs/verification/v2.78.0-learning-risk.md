# v2.78.0 — Learning closeout and risk-based assurance verification

Date: 2026-11-05. Baseline: PHDK 2.77.0, `c86059c7d88a3628acdfa99ad6d5b80a26c15b17`. Scope: owner-authorized canonical standards improvement; no downstream product execution. This is evidence and scenario documentation, not a new permission source.

## Design decisions

Two reusable contracts are introduced, not eight separate workflows: bounded Auto retrospectives and conditional critical-change assurance. Existing Auto/Plan/completion routing carries them into the lifecycle. Existing agent/skill/native routes, explicit-only UAT, host controls, security Preflight, continuity artifacts and machine completion schema remain in force. No agent count/model prescription, paid routing, background service, automatic baseline pinning or local runtime-test permission is added.

## Bounded source-review scenarios

These expected outcomes were reviewed against the policy text. They are NOT runtime or agent-behavior test results.

| Scenario | Required outcome and source |
|---|---|
| Successful Auto with a useful general lesson | Draft indexed process review with final change; report verified delivery then proposal. Retrospective standard, timing/artifact. |
| No useful generalizable finding | Record NO_GENERALIZABLE_FINDINGS; no invented quota or extra agent. Retrospective standard, minimal content. |
| An observed tool denial or misunderstood existing rule | Classify HOST_OR_PROVIDER_LIMIT/MISINTERPRETATION, not automatically a PHDK defect; no evasion. Retrospective standard, classification. |
| Final publication is genuinely blocked | Report partial retrospective and unfinished delivery; never say Auto finished. Retrospective standard, timing. |
| Owner cancels before closure | Stop; no extra report write authorized by a stored rule. Retrospective standard, timing. |
| Missing post-merge report persistence | Disclose partial learning; do not revoke independently verified source delivery or start a self-referential report release. Retrospective standard, timing. |
| Private project proposes a general improvement | Sanitize details and links; no automatic canonical issue/PR or cross-project mutation. Retrospective standard, safe feedback. |
| Low-risk copy-only work | Brief justified NOT_APPLICABLE for critical-change assurance, no empty contract or new approval gate. Critical-change standard, applicability. |
| A new import or permission change, not a legacy rewrite | Apply invariants/authority/evidence/recovery by material risk. Critical-change standard, applicability. |
| Auto Force lacks a material financial/retention/access decision | Recover existing authority or propose a concrete decision; no invented business default; continue independent work. Critical-change standard, decisions. |
| Synthetic characterization cases are authored | Remain NOT RUN until execution is separately permitted; no local-test, new environment or automatic UAT exception. Critical-change standard, characterization. |
| Candidate is merged but acceptance did not run | Source state remains independent of UAT NOT RUN; no ACCEPTED or CUTOVER_EXECUTED claim. Critical-change standard, state table. |
| Application rollback ignores writes after cutover | Recovery contract is insufficient for the dependent transition; define/verify recovery or roll-forward for those writes. Critical-change standard, recovery. |
| Source merge would trigger a destructive startup migration | Block that publication operation absent safe separation or actual authority; do not classify the risk as optional deferred UAT. Critical-change standard, transition. |
| Standards update changes active assumptions | Bounded impact revalidation and refreshed handoff; preserve owner legacy exclusions and security review. No automatic version pin. Critical-change standard, continuity. |

## Generalization dispositions

- Separate delivery, acceptance and cutover: adopted as supplemental semantics, preserving existing source/requirement reconciliation and machine schema.
- Isolated characterization: planning/evidence contract adopted; local execution exception not activated without a separately reviewed and genuinely enforceable isolation design.
- Domain equivalence and migration recovery: generalized by risk; actual mappings, tolerances, balances and business approvals remain local.
- Material decisions, remote continuity, progressive context and baseline impact: clarified by reusing existing mechanisms, not new ledgers, locks, workers or model assumptions.
- Broad duplicated-policy cleanup and configurable baseline pinning: not implemented in this scoped release. Preserve current security review and owner exclusions.

Canonical publication does not synchronize another repository or authorize its product work. The originating project must explicitly adopt the release through the applicable Upgrade contract, preserve customizations, reload relevant rules and fill its local domain/evidence decisions. Bare Upgrade remains narrower than Upgrade Force, which chains into Auto Force; do not invoke Force merely to consume this report.
